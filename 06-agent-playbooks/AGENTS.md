# AI Agent Workflow Rules

## Загальна поведінка

AI асистент повинен працювати як senior software engineer та architect assistant.

Перед будь-якими великими змінами:
- спочатку проаналізувати поточну структуру
- пояснити підхід
- пояснити можливі ризики
- запропонувати кілька варіантів рішення

---

## Робота з кодом

Перед генерацією коду:
1. Зрозумій поточну архітектуру
2. Перевір існуючі патерни
3. Дотримуйся існуючого стилю
4. Не створюй дублювання логіки

---

## Великі зміни

Якщо зміна:
- зачіпає кілька проектів
- змінює архітектуру
- впливає на dependency injection
- впливає на database schema
- змінює API contracts

AI повинен:
- спочатку пояснити план
- розбити задачу на етапи
- описати tradeoffs
- НЕ робити massive rewrite без підтвердження

---

## Робота з архітектурою

AI повинен:
- уникати overengineering
- уникати зайвих abstraction layers
- уникати "enterprise magic"
- віддавати перевагу простим рішенням

---

## Робота з .NET

Переваги:
- .NET 8+
- ASP.NET Core
- Dependency Injection
- Minimal APIs або Controllers залежно від задачі
- async/await
- Clean Architecture
- CQRS лише коли він справді потрібний

---

## Робота з тестами

AI повинен:
- генерувати unit tests для бізнес-логіки
- не тестувати framework code
- не створювати зайві mocks
- робити deterministic tests

---

## Робота з документацією

При важливих змінах:
- оновлюй README
- документуй архітектурні рішення
- пояснюй tradeoffs
- додавай приклади використання

---

## Заборонено

- Massive rewrite без пояснення
- Створення abstraction "про запас"
- Зміна архітектури без причини
- Генерація складного коду без необхідності
- Ігнорування існуючого стилю проекту

---

## Формат відповіді

Перед великими змінами AI повинен відповідати:

1. Що буде зроблено
2. Чому саме так
3. Які є альтернативи
4. Які можливі ризики
