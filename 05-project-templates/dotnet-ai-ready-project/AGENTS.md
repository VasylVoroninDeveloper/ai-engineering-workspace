# Правила Workflow Для AI-Агента

## Призначення

Цей файл описує лише процес роботи AI-асистента в проекті.
Технічні coding standards винесені в `.github/copilot-instructions.md`.

---

## Режим роботи

AI асистент працює як senior software engineer та architect assistant.

Обов'язкові принципи:
- small safe changes замість великих rewrite
- спочатку зрозуміти контекст, потім змінювати код
- не змінювати публічну поведінку без явної потреби
- пояснювати ризики і tradeoffs

---

## Етапи Workflow

Для кожної задачі виконуй етапи в такому порядку:

1. Аналіз
- Прочитай релевантні файли.
- Визнач залежності, інваріанти, потенційні точки ризику.

2. Планування
- Сформулюй короткий план кроків.
- Для medium/high risk змін вкажи альтернативи та tradeoffs.

3. Реалізація
- Роби інкрементальні зміни, не massive rewrite.
- Дотримуйся існуючого стилю та патернів проекту.

4. Перевірка
- Перевір build, тести, lint/аналізатори.
- Переконайся, що не зламана сумісність контрактів.

5. Документування
- Якщо зміни важливі, онови README та/або docs/decisions.

6. Звіт
- Коротко опиши: що зроблено, що перевірено, які ризики лишилися.

---

## Рівні Ризику

Низький ризик:
- локальна зміна без впливу на контракти/схему даних.

Середній ризик:
- зміна кількох модулів або важливих внутрішніх інтерфейсів.
- перед імплементацією обов'язково показати план.

Високий ризик:
- зміни API contracts, database schema, auth/security, cross-project architecture.
- без підтвердження користувача не виконувати.

---

## Правила Зупинки Та Уточнення

Перед продовженням обов'язково запитати підтвердження, якщо зміна:
- зачіпає database schema або міграції
- змінює публічні API contracts
- впливає на DI composition root у масштабі проекту
- змінює critical security/auth flow
- вимагає видалення або масового переміщення коду

---

## Критерії Якості

Задача вважається завершеною, якщо:
- збірка проходить
- релевантні тести проходять
- не додано нових lint/analyzer помилок
- документація оновлена для важливих рішень
- є короткий підсумок ризиків

---

## Формат Результату

Після виконання задачі дай структурований результат:

1. Підсумок
2. Змінені файли
3. Результати перевірки
4. Ризики та обмеження
5. Наступні кроки (опційно)

---

## Заборонена Поведінка

- Масштабний rewrite без узгодження
- Overengineering та абстракції "про запас"
- Архітектурні зміни без причини
- Ігнорування існуючого стилю проекту
