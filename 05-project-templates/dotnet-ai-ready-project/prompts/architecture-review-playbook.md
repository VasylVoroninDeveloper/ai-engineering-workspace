# Playbook: Огляд Архітектури

## Мета
Оцінити поточну архітектуру та виявити ризики, зайву складність і проблеми підтримуваності.

## Вхідні дані
- Релевантні шляхи проекту/модулів
- Поточні обмеження (дедлайн, продуктивність, розмір команди)
- Нефункціональні вимоги

## Інструкції Для AI
1. Змоделюй поточні архітектурні межі та залежності.
2. Визнач порушення: coupling, layer leakage, дублювання, oversized services.
3. Класифікуй findings за критичністю: Critical, Major, Minor.
4. Запропонуй мінімальні інкрементальні виправлення (без massive rewrite).
5. Вкажи, що варто залишити без змін.

## Формат Відповіді
1. Загальна оцінка (2-4 речення)
2. Findings за критичністю
3. Рекомендовані зміни (за пріоритетом)
4. Ризики та tradeoffs
5. Безпечний наступний крок (найменша high-impact дія)

## Обмеження
- Зберігай стабільну поточну поведінку системи.
- Уникай overengineering і спекулятивних абстракцій.
- Якщо зміни впливають на API contracts або DB schema, спочатку попроси підтвердження.
