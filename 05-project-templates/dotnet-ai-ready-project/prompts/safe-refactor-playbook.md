# Playbook: Безпечний Рефакторинг

## Мета
Провести рефакторинг для кращої читабельності та підтримуваності без зміни поведінки.

## Вхідні дані
- Цільові файли/модулі
- Поточні проблеми (дублювання, складність, naming)
- Статус покриття тестами

## Інструкції Для AI
1. Поясни поточні проблеми та очікувані покращення.
2. Запропонуй покроковий план рефакторингу.
3. Внось зміни невеликими commit/chunk порціями.
4. Зберігай публічні контракти, якщо не запитано інше.
5. Додай/онови unit tests для зміненої бізнес-логіки.

## Формат Відповіді
1. Намір рефакторингу
2. Заплановані кроки
3. Змінені файли
4. Виконана перевірка (build/tests)
5. Залишкові ризики

## Обмеження
- Без massive rewrite.
- Без architecture redesign без погодження.
- Зберігай стиль і конвенції існуючого codebase.
